# 配色参考（让高亮看起来像参考图）

> 背景：把关键字按语义拆成 8 类 scope 之后，用户在编辑器里看到的**仍然全是同一种蓝色**。
> 本文解释原因，并给一个确定性的解法。

---

## 0. 改颜色之前先确认：生效的是哪个 grammar

**换主题也不变色，说明可能根本不是主题的问题。**

宿主窗口（F5 打开的那个）默认会加载**所有已装扩展**。如果机器上装了
`mshr-h.veriloghdl`、`teros-technology.teroshdl`、`sterben.fpga-support` 之类的 HDL 插件，
它们**也会给 `verilog` 注册 grammar**，而 VSCode 对同语言的多个 grammar 只用一个 —— 谁最后注册谁生效。

于是会出现：改了本插件的 grammar，屏幕上却毫无变化。

### 两步确认

**① 直接查扩展**

```
Ctrl+Shift+P → "VeriKit: 诊断语言与着色"
```

Output 面板会列出所有给 `verilog` / `systemverilog` 提供语言或 grammar 的扩展，
以及当前 `languageId`、当前主题名。**如果列出两个以上，就说明着色可能不是本扩展的。**

**② 干净环境复验**

```
运行面板 → 选 "运行扩展（干净环境：禁用其他扩展）" → F5
```

这个启动配置带了 `--disable-extensions`，宿主只加载本扩展。此时看到的颜色一定是本插件的 grammar 产出的。

**③（可选）看单点的 scope**

```
把光标放在某个关键字上 → Ctrl+Shift+P → "Developer: Inspect Editor Tokens and Scopes"
```

弹窗里会显示该位置的 scope 栈。本插件的 `always` 应是 `keyword.control.verilog`；
如果是别的名字，说明用的不是我们的 grammar。

---

## 1. 为什么拆了 scope 还是全蓝

TextMate 的着色链条是三段：

```
正则匹配 → 产出 scope 名（如 keyword.control.verilog）→ 主题按 scope 查表决定颜色
```

**插件只负责第二段。** 第三段的查表规则完全由当前颜色主题掌握。

如果主题里 `keyword.control`、`keyword.other`、`storage.type` 都映射到同一个颜色，
那么无论我们把 scope 拆成 4 类还是 40 类，屏幕上都是同一种蓝。

**实测线索**：拆分后 `module`(keyword.other.module) / `input`(storage.type) /
`begin`(keyword.other.block) / `always`(keyword.control) 四种不同 scope 仍然同色
→ 说明当前主题把它们抹平了。

常见的两套内置主题差别就在这里：

| 主题 | 表现 |
|---|---|
| **Light Modern / Dark Modern**（VSCode 1.7x 起的默认） | 关键字类基本统一成一种蓝，整体更"扁平" |
| **Light+ / Dark+**（原版 "Visual Studio" 主题） | 控制关键字紫、类型与块蓝、实体名青，层次更分明 |

参考图的效果更接近 **Light+ / Dark+** 或第三方主题。

---

## 2. 确定性解法：把配色显式写进设置

不想换主题、或想精确控制某个词的颜色，就显式指定。把下面这段贴进
**用户 `settings.json`**（`Ctrl+Shift+P` → `Preferences: Open User Settings (JSON)`）。

```jsonc
"editor.tokenColorCustomizations": {
  "textMateRules": [
    // 控制流：紫
    { "scope": "keyword.control.verilog",            "settings": { "foreground": "#AF00DB" } },
    { "scope": "keyword.control.task.verilog",        "settings": { "foreground": "#AF00DB" } },
    { "scope": "keyword.control.preprocessor.verilog", "settings": { "foreground": "#AF00DB" } },
    // 参数/修饰：紫（参考图里 parameter 就是紫的）
    { "scope": "storage.modifier.verilog",            "settings": { "foreground": "#AF00DB" } },
    // 块、类型、模块关键字：蓝
    { "scope": "keyword.other.block.verilog",         "settings": { "foreground": "#0000FF" } },
    { "scope": "keyword.other.edge.verilog",          "settings": { "foreground": "#0000FF" } },
    { "scope": "keyword.other.module.verilog",        "settings": { "foreground": "#0000FF" } },
    { "scope": "storage.type.verilog",                "settings": { "foreground": "#0000FF" } },
    // 实体名：青
    { "scope": "entity.name.type.module.verilog",     "settings": { "foreground": "#267F99" } },
    { "scope": "entity.name.function.verilog",        "settings": { "foreground": "#267F99" } },
    // 数字与字符串
    { "scope": "constant.numeric.verilog",            "settings": { "foreground": "#098658" } },
    { "scope": "string.quoted.double.verilog",        "settings": { "foreground": "#A31515" } },
    // 系统任务 $display / $finish
    { "scope": "support.function.system.verilog",     "settings": { "foreground": "#795E26" } },
    // 运算符
    { "scope": "keyword.operator.verilog",            "settings": { "foreground": "#0000FF" } },
    // 注释（一般主题已够，写上是防止被别的规则覆盖）
    { "scope": "comment.line.double-slash.verilog",   "settings": { "foreground": "#008000" } },
    { "scope": "comment.block.verilog",               "settings": { "foreground": "#008000" } }
  ]
}
```

深色主题把色值换成这套：

| 用途 | 浅色主题 | 深色主题 |
|---|---|---|
| 控制流 / 参数 | `#AF00DB` | `#C586C0` |
| 块 / 类型 / 模块关键字 | `#0000FF` | `#569CD6` |
| 模块名 / 函数名 | `#267F99` | `#4EC9B0` |
| 数字 | `#098658` | `#B5CEA8` |
| 字符串 | `#A31515` | `#CE9178` |
| 系统任务 | `#795E26` | `#DCDCAA` |
| 注释 | `#008000` | `#6A9955` |

## 3. 为什么不由插件硬塞这些颜色

技术上有两条路，都不建议：

| 做法 | 问题 |
|---|---|
| `contributes.configurationDefaults` 里写 `editor.tokenColorCustomizations` | 等于替用户决定配色；用户换主题后颜色会"不跟着变"，很怪 |
| 自带一个主题（`contributes.themes`） | 侵入性更大，而且只在用户主动选中时才生效 |

**语言插件的职责是把 scope 分对**，颜色交给主题。上面那段是"如果你想精确还原参考图"的可选补充，
不需要的话直接删掉即可，删掉只会回到当前主题的默认配色，不会破坏任何功能。

## 4. 参考图里有一件事我们做不到

参考图 2 里 `vld_d`、`sh_period` 这些**标识符也有颜色**，而 `clk`、`rst_n` 是黑的。

那属于 **semantic tokens（语义着色）** —— 需要知道"这个名字是信号、端口还是参数"。
TextMate grammar 是纯正则，没有符号表。要那种效果，得等 S3a/S3b 的模块头解析 +
索引做完之后，把解析结果作为 `SemanticTokensProvider` 提供给编辑器。
